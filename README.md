# DAYLUNG

AI-консультант по выбору цифровых сервисов. Публичная часть + защищённая админка с версиями, предпросмотром и откатом.

Проект на чистом Node.js без фреймворков: собственный роутер, серверный рендеринг HTML, слой хранения с двумя драйверами.

---

## Быстрый старт

```bash
# 1. зависимости (единственная — драйвер PostgreSQL)
npm install

# 2. конфигурация
cp .env.example .env
# откройте .env и задайте ADMIN_PASSWORD и SESSION_SECRET

# 3. запуск
npm start
```

Сайт: http://127.0.0.1:3000
Админка: http://127.0.0.1:3000/admin

При первом запуске данные создаются автоматически из seed (4 категории, 12 сервисов, 5 рекомендаций).

**Требуется Node.js 20 или новее.** Больше ничего устанавливать не нужно.

## Переменные окружения

Все секреты — только в `.env` (в git не попадает) или в переменных окружения платформы.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `PORT` | нет | Порт, по умолчанию 3000 |
| `HOST` | нет | Адрес, по умолчанию 127.0.0.1 |
| `APP_URL` | нет | Публичный адрес сайта |
| `ADMIN_USER` | нет | Логин владельца, по умолчанию `owner` |
| `ADMIN_PASSWORD` | **да** | Пароль в админку. Без него вход заблокирован |
| `SESSION_SECRET` | **да** для прода | Ключ подписи cookie. Без него на serverless вход ломается |
| `SESSION_TTL_HOURS` | нет | Время жизни сессии, по умолчанию 12 |
| `DATA_DIR` | нет | Папка данных для файлового драйвера |
| `DB_DRIVER` | нет | `file` (по умолчанию) или `postgres` |
| `DATABASE_URL` | для postgres | Строка подключения к БД |
| `AI_PROVIDER` | нет | Провайдер AI, по умолчанию `mock` |
| `AI_API_KEY` | нет | Ключ AI. Не задан — работает mock |
| `AFFILIATE_TRACKING` | нет | Учёт переходов по партнёрским ссылкам |

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запуск сервера |
| `npm run dev` | Запуск с автоперезапуском при изменении файлов |
| `npm run check` | Проверка модулей, данных, отсутствия секретов в коде и доступности страниц |
| `npm run db:check` | Проверка слоя хранения: запись, чтение, update, блобы, конкурентные записи |
| `npm run seed` | Создаёт недостающие данные. **Существующие не трогает** |
| `npm run reset -- --yes` | Сбрасывает данные к seed. Перед сбросом делает копию |

`npm run check` проверяет страницы только если сервер уже запущен на порту из `.env`.

## Хранение данных

Два драйвера, выбор через `DB_DRIVER`. Прикладной код от выбора не зависит — всё идёт через `src/db/store.js`.

**`file`** — JSON-файлы в `data/`. Запись атомарная (временный файл + rename), операции сериализуются очередью в памяти. Подходит для локальной разработки и одного сервера.

**`postgres`** — таблицы `daylung_tables` (одна строка на таблицу, JSONB) и `daylung_blobs` (снимки версий и бэкапы). Схема создаётся при первом запросе. `update()` работает в транзакции с `SELECT … FOR UPDATE`, поэтому параллельные записи из разных инстансов не теряются.

```bash
# локальный Postgres
createdb daylung
DB_DRIVER=postgres \
DATABASE_URL="postgresql://user:pass@localhost/daylung" \
npm start
```

Миграция с файлов на Postgres: запустите приложение с `DB_DRIVER=postgres` на пустой базе — создастся seed. Существующие правки переносятся вручную (или `npm run seed` на файлах, затем экспорт).

## Как менять сайт

**Тексты главной** — `src/views/home.js`. Тексты заголовка и примеры запросов также редактируются в админке: `/admin/settings`.

**Цвета и типографика** — токены в начале `public/css/base.css`.

**Новая категория** — через админку (`/admin/categories`), без правки кода.

**Новый сервис** — `/admin/services`. Поля: название, slug, категория, описание, цена, рейтинг, плюсы, минусы, платформы, официальная и партнёрская ссылки, статус публикации.

**Правка кода** — раздел «Доработка сайта» (`/admin/editor`). Инструкция или вставленный компонент создают версию-**предпросмотр**: рабочий сайт не меняется, пока вы не нажмёте «Применить». Вставленный код проверяется и не исполняется на сервере.

**Откат** — `/admin/versions`. Любую версию со снимком можно восстановить; перед откатом автоматически сохраняется текущее состояние.

## Деплой на Vercel

В проекте уже есть `api/index.js` и `vercel.json`. На Vercel **обязателен Postgres**: файловая система там доступна только на чтение.

1. Создайте базу (Neon, Supabase или Vercel Postgres)
2. В настройках проекта на Vercel добавьте переменные:
   - `DB_DRIVER=postgres`
   - `DATABASE_URL` — строка подключения
   - `SESSION_SECRET` — случайная строка, **обязательно**
   - `ADMIN_PASSWORD` — сильный пароль
   - `ADMIN_USER` — логин
3. Задеплойте
4. Проверьте: `npm run db:check` против боевой базы, затем вход в `/admin`

Без `SESSION_SECRET` каждый serverless-инстанс подписывает cookie своим ключом, и вход будет слетать.

## Что уже работает

- Публичная часть: главная, 4 категории, карточки сервисов, поиск, подбор (mock)
- Админка: вход, дашборд, категории (порядок, вкл/выкл), сервисы, рекомендации, настройки
- Версии: снимки, предпросмотр, применение, откат, резервные копии
- Безопасность: CSRF, сессии на подписанном cookie, лимит попыток входа (общий для всех инстансов, хранится в БД), санитайзер вставленного кода
- Два драйвера хранения, одинаково проходящие полный сценарий

## Что не реализовано

- Реальный AI-провайдер: `src/services/ai/recommend.js` работает на mock, точка подключения помечена
- Партнёрские программы: ссылки и учёт переходов есть, реальных программ нет
- Мультипользовательский режим: один владелец, задаётся через `.env`
- Автоматических тестов (Jest/Vitest) нет: проверки через `npm run check`, `npm run db:check` и сценарии вручную
